# DyntraLB TTFT comparison revision

This revision targets waiting before the first generated token. It does not
claim a measured NPU performance improvement. Keep CP disabled and retain the
original graph execution settings for the first comparison. MTP is not required.

## Choose a policy separately from the activation mode

`mode` still accepts `static` and `dynamic`: it controls when LB is active.
The new `policy_profile` controls which planner and admission policy to use.

| `policy_profile` | Planner and admission behavior |
| --- | --- |
| `original` | The original PR #12292 planner and block-based pause/admission policy. No forced resume after four steps. |
| `tpot` | The previous revision with request identity, throughput/pause guards, and overdue resume protection. This remains the default for existing configurations. |
| `ttft` | The original planner with the first-token changes described below. No forced rotation of already-generating requests after four steps. |

The original planner function is copied from PR head
`2a982061275a8de5f9a05a99ae5adb9d6a1d0b50`, including its 1000-iteration
search limit and latency coefficients. Golden test outputs were generated by
executing that pinned function. This is a policy rollback for comparison,
not a checkout of the entire old repository: installation fixes, runtime
compatibility, snapshot construction, and collective-window fixes are retained.

The original heuristic's limitations are deliberately retained in the
`original` and `ttft` planners to isolate the new first-token policy.
`min_throughput_gain`, `max_pauses_per_rank`, `max_pause_steps`, `min_run_steps`,
and custom latency coefficients apply to `tpot`, not these two profiles.

## What changes in the TTFT profile

1. A running request with `num_output_tokens == 0` is protected from LB pauses.
   Memory preemption and other normal scheduler constraints still apply.
   Once it has generated output, it follows the original LB pause policy.
2. A ready waiting request that has not generated output counts the scheduler
   steps on which the LB gate rejects it. Repeated calls in one step count once.
   After `first_token_max_lb_wait_steps` deferrals (default 4), it can bypass
   that gate. This history is retained when a selection cannot proceed because
   of KV or token budgets, and removed when the request finishes or produces
   output and reaches the gate again.
3. At most `first_token_max_admissions_per_step` distinct requests per DP rank
   receive an extra admission attempt per step (default 1). There is no forced
   eviction of running decode requests to make room. Queue ordering is retained.
4. A TTFT plan is consumed once. It is not replayed on later scheduler steps.

This is a bound on LB-only deferrals before bypass eligibility, not a guarantee
of receiving a token within four steps. The per-step cap, lack of a free batch
slot, remote KV readiness, async output, token budget, LoRA, memory, or prefill
work can still delay a request. The normal scheduler enforces these conditions.
Protecting first-token work or admitting more work can increase step latency
and TPOT. Measure all three metrics rather than optimizing TTFT alone.
For disaggregated P/D, this policy only affects the scheduler where it is
enabled; it cannot bound prefill queueing, KV transfer, or client/network time.

## Server comparison

Use the same container and installed Python environment as the working service.
This revision changes Python code only. When the existing editable installation
already points at the updated source directory and no native files changed,
restart the service to load it; a new native build is not needed for this delta.
Deploy the complete source update, including `dyntra_lb_original.py`.

Keep model, TP/DP/EP, graph settings, connector, dataset/order, concurrency,
sampling/output limits, and diagnostics identical. Do not add `--enforce-eager`
for these CP-disabled profiles. Keep `start_step=0`, `balance_interval=1`,
`bubble_threshold=5.0`, `long_req_block_threshold=700`, and
`dynamic_max_step=256` for the first dynamic comparison.

Complete `additional_config` fragments are provided in:

- `examples/dyntra_lb/bl.json`
- `examples/dyntra_lb/dynam_original.json`
- `examples/dyntra_lb/dynam_tpot.json`
- `examples/dyntra_lb/dynam_ttft.json`

Merge the fragment into the existing `additional_config`; keep connector and
other settings. Each fragment is a separate run, not four configurations to
pass together. To use static activation instead, change `mode` to `static` in
both compared configurations and keep their thresholds identical.

Compare BL, original, previous (`tpot`), and new (`ttft`) profiles using repeated
runs. Save each run's benchmark JSON with detailed per-request results. Report
mean and p99 TTFT, TPOT, ITL, output throughput, failures, and between-run
variation. Aggregate averages alone cannot show which requests LB delayed.
Only after the initial comparison, try first-token limits of 2, 4, and 8.

For a short diagnosis run, enable `enable_diagnostics=true` and look for
`DYNTRA_TTFT_BYPASS request_id=... step=...`. It indicates the LB gate opened,
not successful scheduling or token delivery. Disable diagnostics for timing.
The `original` and `ttft` profiles reject CP at startup to keep this comparison
independent of eager execution and experimental cross-rank KV transfers.

## Verification scope

CPU tests cover the pinned original planner's outputs, all three profile
dispatch paths, repeated gate deferrals, per-rank bypass limits, cleanup,
first-token pause protection, and preservation of existing decode admission.
Existing standalone tests cover the previous guarded profile and CPU CP
runtime contracts. They do not establish Ascend performance or full-model
correctness. NPU validation must run on the server.

The final standalone suite passed 264 tests locally, including real CPU
multi-process Gloo transfers and local CMake dependency preparation. Changed
Python files passed Ruff and the new document passed Markdownlint. The required
full `bash format.sh ci` invocation stopped during Node tool installation
because a download was incomplete; the full hook suite did not complete.

```bash
python -m pytest -q tests/standalone
```
